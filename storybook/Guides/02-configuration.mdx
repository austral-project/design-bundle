# Configuration

`Config` is a singleton that holds the runtime state of the bundle. Its most
common use is enabling or disabling modules and components. Every call below must
happen **before** `Loader.initialize()`.

```js
import { Config } from "@austral/design";
```

All disable/enable methods are **case-insensitive** — `"Mercure"` and
`"mercure"` are equivalent (names are lower-cased internally).

## Modules

Modules are the top-level features loaded by `Loader`. Disable the ones you
don't need:

```js
Config.disableModule("Mercure");
Config.disableModule("Storybook");
```

A common pattern is to enable Storybook-only modules conditionally:

```js
if (window.STORYBOOK === undefined) {
  Config.disableModule("AlertSwal");
  Config.disableModule("Storybook");
}
```

### Optional modules

The core calls two modules when they exist, so a project can add page transitions or scroll animations without
changing the bundle. Register them with `Config.addModule()` before `Loader.initialize()`:

<table>
  <thead>
    <tr>
      <th>Module name</th>
      <th>Methods called</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>PageTransition</code></td>
      <td><code>transitionStart(transition)</code>, <code>transitionScroll(...)</code>, <code>transitionEnd()</code></td>
    </tr>
    <tr>
      <td><code>ScrollAnimate</code></td>
      <td><code>execute()</code></td>
    </tr>
  </tbody>
</table>


## Components

Components are individual UI elements instantiated on matching DOM nodes. Disable
one by its identifier:

```js
Config.disableComponent("button-animate");
Config.disableComponent("textarea");
```

## Other Config helpers

`Config` also exposes general-purpose stores, useful when writing hooks or custom
modules:

<table>
  <thead>
    <tr>
      <th>Method</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>setParameter(key, value)</code> / <code>getParameter(key, default)</code></td>
      <td>Arbitrary key/value parameters.</td>
    </tr>
    <tr>
      <td><code>setObject(key, obj)</code> / <code>getObject(key)</code></td>
      <td>Store/retrieve shared objects.</td>
    </tr>
    <tr>
      <td><code>getUserId()</code></td>
      <td>Reads <code>body[data-user-id]</code> (cached).</td>
    </tr>
    <tr>
      <td><code>getMousePosition()</code> / <code>setMousePosition(x, y)</code></td>
      <td>Current cursor position.</td>
    </tr>
    <tr>
      <td><code>getModule(name)</code> / <code>hasModule(name)</code></td>
      <td>Access a loaded module instance.</td>
    </tr>
    <tr>
      <td><code>dispatchAllComponents(eventName, data)</code></td>
      <td>Dispatch a DOM event to every registered component.</td>
    </tr>
  </tbody>
</table>

Enabling a previously disabled item is also possible: `enableModule(name)` and
`enableComponent(name)`.
