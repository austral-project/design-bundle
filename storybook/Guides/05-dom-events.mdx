# DOM Events

Alongside **Hooks**, the bundle uses a DOM event bus: `DomEventManager`. The two
systems are different and complementary:

<table>
  <thead>
    <tr>
      <th></th>
      <th><strong>Hooks</strong></th>
      <th><strong>DOM Events</strong></th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Purpose</td>
      <td>Intercept/alter lifecycle logic</td>
      <td>Broadcast/react to things happening</td>
    </tr>
    <tr>
      <td>Async</td>
      <td>Awaited, sequential</td>
      <td>Fire-and-forget</td>
    </tr>
    <tr>
      <td>Return value</td>
      <td>Can mutate payload or cancel (<code>false</code>)</td>
      <td>Ignored</td>
    </tr>
    <tr>
      <td>Target</td>
      <td>Global registries</td>
      <td>Any DOM node (defaults to <code>document</code>)</td>
    </tr>
  </tbody>
</table>

Use a **hook** when you need to change behavior or cancel an action; use a **DOM
event listener** when you just need to react to something.

```js
import { DomEventManager } from "@austral/design";
```

## API

```js
// Dispatch
DomEventManager.dispatch(type, data = {}, target = document);

// Listen (type can be a string or array of strings)
DomEventManager.addListener(type, callback, target = document, options = false);

// Remove one listener (same type + same original callback reference)
DomEventManager.removeListener(type, callback, target = document);

// Remove all listeners on a target (or only those of one event type)
DomEventManager.removeAllListeners(target = document, removeEvent = "all");
```

Notes:

- The payload passed to `dispatch` arrives on the listener as
  `event.detail`.
- Listeners are wrapped in a try/catch: an error inside one listener is logged
  via `Debug` and won't break the others.
- `removeListener` matches on the **original** callback reference, so keep a
  reference to named functions if you plan to remove them.
- Events are dispatched as `CustomEvent` with `cancelable: true`.

```js
function onLoad(event) {
  console.log(event.detail);
}
DomEventManager.addListener("modules::load", onLoad);
// later
DomEventManager.removeListener("modules::load", onLoad);
```

### Keyboard

The `Keyboard` module emits dynamic events per key:

<table>
  <thead>
    <tr>
      <th>Pattern</th>
      <th>Example</th>
      <th>Meaning</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>keyDown:&lt;key&gt;</code></td>
      <td><code>keyDown:shift</code></td>
      <td>Key pressed down.</td>
    </tr>
    <tr>
      <td><code>keyPress:&lt;key&gt;</code></td>
      <td><code>keyPress:*</code></td>
      <td>Key press.</td>
    </tr>
    <tr>
      <td><code>keyUp:&lt;key&gt;</code></td>
      <td><code>keyUp:*</code></td>
      <td>Key released.</td>
    </tr>
  </tbody>
</table>

`*` matches any key; specific variants (e.g. `shift`) target that key.
